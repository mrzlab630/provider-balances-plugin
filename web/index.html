Поставщики

Новый поставщик

Адрес сайта личного кабинета. Без /console и /api/user/self.

В режиме «Авто» используется валюта поставщика. Если она не указана, показываются единицы баланса.

До 24 символов: знак, код, слово или эмодзи.

Скопируйте значение Authorization из запроса /api/user/self в DevTools → Network.

Для сессий New API с cookie new_api_refresh. При запросе баланса сервер получит новый токен, если старый истёк или скоро истечёт.

Cookie new_api_refresh имеет флаг HttpOnly и путь /api/user/auth, поэтому её может не быть в обычном списке Cookies и document.cookie. В DevTools → Network найдите POST /api/user/auth/refresh и скопируйте весь Request Headers → Cookie. Токен доступа можно оставить пустым — сервер получит его сам. Сохранённая cookie не передаётся обратно в интерфейс.

Используйте отдельную сессию входа для плагина: refresh-cookie меняется при обновлении, и параллельное использование этой сессии в браузере может отозвать доступ. Если сессия истечёт или будет закрыта, понадобится новая cookie.

Нужен некоторым старым версиям New API. Скопируйте New-Api-User из того же запроса.

Где взять токен или cookie
  1. Войдите в личный кабинет поставщика и откройте инструменты разработчика (F12).
  2. На вкладке Network обновите страницу и найдите запрос /api/user/self.
  3. В Request Headers скопируйте значение Authorization. Если такого заголовка нет, выберите «Cookie сессии» и скопируйте значение Cookie.
  4. Если есть заголовок New-Api-User, скопируйте его в одноимённое поле.

Для автообновления Bearer включите переключатель, найдите в Network запрос POST /api/user/auth/refresh и скопируйте весь Request Headers → Cookie. Cookie new_api_refresh скрыта как HttpOnly, поэтому её часто нет в Application → Cookies или document.cookie. Публичная new_api_has_session=1 только сообщает о наличии сессии и не может заменить refresh-cookie. Новый токен и ротация refresh-cookie сохраняются сервером автоматически.

Не публикуйте Cookie-заголовок в чате или тикетах: он даёт доступ к сессии. Поставщик должен поддерживать New API POST /api/user/auth/refresh; для других механизмов обновления нужна отдельная интеграция.

Данные сохраняются на сервере в файле с доступом только для владельца. Сохранённые токен и refresh-cookie не передаются обратно в интерфейс.

Балансы обновляются вручную. Сумма рассчитывается по настройкам поставщика. Для каждого поставщика можно выбрать своё обозначение валюты без конвертации суммы.
